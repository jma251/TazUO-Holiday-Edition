# Server -> Client Packet Handlers, 0xB0 – 0xFF

Scope: 45 packets. Default file for bare `line` references is
`src/ClassicUO.Client/Network/PacketHandlers.cs`; all other files are named.
Lengths come from `src/ClassicUO.Client/Network/PacketsTable.cs`; a fixed length
seeds the reader at offset 1, a `-1` (variable) length seeds it at offset 3
(`PacketHandlers.cs:217-228`, seek at `:191`). `StackDataReader`'s indexer
ignores its argument and always returns `_data[0]`, i.e. the packet ID byte
(`ClassicUO.IO/StackDataReader.cs:39`) — several handlers branch on `p[0]`.

---

### 0xB0 OpenGump

- **Purpose** — Uncompressed generic gump: layout command string plus an array of Unicode text lines.
- **Wire** — variable (`PacketsTable.cs:217`), offset 3. `[3..6]` u32BE sender (4071); `[7..10]` u32BE gumpID (4072); `[11..14]` u32BE cast to int x (4073); `[15..18]` u32BE cast to int y (4074); `[19..20]` u16BE cmdLen (4076) then cmdLen ASCII bytes cmd (4077); u16BE textLinesCount (4079); per line u16BE length (4085), `ReadUnicodeBE(length)` where length is a CHARACTER count — size = length*2 (`StackDataReader.cs:415,471`) — else `string.Empty` (4089/4093). `ReadString` truncates each line at the first embedded NUL while still advancing length*2 (`StackDataReader.cs:429-430`).
- **Mutates** — `UIManager._gumpPositionCache[gumpID] = new Point(x,y)` at 6964 → `UIManager.cs:297`, only on first sight of the gumpID; `World.Player.HasGump = true` (7624), `World.Player.LastGumpID = gumpID` (7625); `ScriptRecorder.Instance.RecordWaitForGump` (6926); `ScriptingInfoGump.AddOrUpdateInfo("Last Gump Opened", …)` (6927); `UIManager.Gumps` prepend + `_needSort` (7532 → `UIManager.cs:485,492`); reuse path wipes children with `g.Clear()` (6954) and rebuilds `PacketGumpText` (6981, 6998); per-token `CanCloseWithRightClick=false` (7350), `CanCloseWithEsc=false` (7356), `CanMove=false` (7362). No World/Item/Mobile/chunk writes.
- **Creates** — `new Gump(sender, gumpID)` with X/Y, `CanMove=true`, `CanCloseWithRightClick=true`, `CanCloseWithEsc=true`, `InvalidateContents=false`, `IsFromServer=true` (6969-6978), unless an existing gump is reused. One control per layout token: Button (7002), ButtonTileArt (7012), CheckerTrans (7022), CroppedText (7037), GumpPic (7044, 7502), ResizePic (7307), Label (7313), StbTextBox (7329), StaticPic (7344), RadioButton (7373), Checkbox (7379), RenderedMapArea (7521), html/tooltip controls. SOS gumps only: MenuButton + ContextMenuControl (7583-7616) and a WorldMapGump if none exists when an entry is clicked (7595, 7606).
- **Destroys** — nothing is disposed; the reuse path only `Clear()`s children (6954).
- **Triggers** — `UIManager.Add` (7532), `gump.Update()` (7535), `gump.SetInScreen()` (7536); `GameActions.Print` of the gump ID under `CUOEnviroment.Debug` (7540) and of decoded SOS coordinates (7581); `ApplyTrans` over existing children per checkertrans token (7024 → 7674). No outgoing packet.
- **Ignores / partial** — returns if `World.Player == null` (4066). `CreateGump` returns null if the tokenized layout has no tokens (6931-6934). Server x/y are DISCARDED whenever a cached position exists for the gumpID (6941-6942). The reuse-in-place branch is only reachable inside that cached-position branch and only for a non-disposed gump with `LocalSerial == sender && ServerSerial == gumpID` (6952). Zero-parameter tokens skipped (6992-6995). Unrecognised commands logged "Invalid Gump Command" and dropped (7526). `text` needs Count >= 5 (7311); `page` needs >= 2 (7298); `maparea` needs >= 10 with all nine ints parsing (7510-7519); `gumppichued`/`gumppicphued` need >= 3 (7501). `togglelimitgumpscale` is recognised and deliberately does nothing (7504-7507). `group`/`endgroup` only bump a counter passed to RadioButton (7369, 7373). SOS post-processing requires `ProfileManager.CurrentProfile != null && gumpID == CurrentProfile.SOSGumpID` (7543-7545) and breaks below four coordinate matches (7564-7565). A finished gump at 0,0 is re-centred in the viewport, overriding both server and cached position (7628-7632). x/y arrive as u32 and are cast to int (4073-4074), so > int.MaxValue becomes negative.

### 0xB2 ChatMessage

- **Purpose** — Chat-system control and traffic: conference create/destroy/join/leave, enable/disable, user-list churn, chat text.
- **Wire** — variable (`PacketsTable.cs:219`), offset 3. `+3` u16BE cmd (4126). 0x03E8: skip 4 (4131), UnicodeBE null-terminated channelName (4132), u16BE == 0x31 → hasPassword (4133). 0x03E9: skip 4 (4142), UnicodeBE channelName (4143). 0x03EB, 0x03EC, 0x03F0: nothing further. 0x03ED: skip 4 (4164), UnicodeBE username (4165). 0x03EE: skip 4 (4172), u16BE userType (4173), UnicodeBE username (4174). 0x03EF: skip 4 (4179), UnicodeBE username (4180). 0x03F1: skip 4 (4188), UnicodeBE channelName (4189). 0x03F4: skip 4 (4199), UnicodeBE channelName (4200). 0x0025/0x0026/0x0027: skip 4 (4209), u16BE msgType (4210), UnicodeBE username (4211), UnicodeBE msgSent (4212). default (cmd 0x0001-0x0024, 0x0028-0x002C): skip 4 (4244), UnicodeBE text (4245).
- **Mutates** — `ChatManager.CurrentChannelName` (4134, 4190); `ChatManager.Channels` add (4135 → `ChatManager.cs:96-103`) / remove (4144 → `ChatManager.cs:105-111`) / clear (4156 → `ChatManager.cs:113-116`); `ChatManager.ChatIsEnabled` = EnabledUserRequest (4151), Disabled (4157), Enabled (4166). No World/Item/Mobile/Chunk/House state.
- **Creates** — `ChatChannel` objects (`ChatManager.cs:99`); journal/overhead text indirectly via `GameActions.Print` and `MessageManager.HandleMessage`.
- **Destroys** — ChatGump disposed on 0x03EC (4159); channel entries removed on 0x03E9 (4144) and all on 0x03EC (4156).
- **Triggers** — `ChatGump.RequestUpdateContents` (4137, 4146), `ChatGump.UpdateConference` (4192); OUTGOING `NetClient.Socket.Send_ChatJoinCommand("General")` on 0x03ED (4167); `GameActions.Print` (4194, 4202, 4267); `MessageManager.HandleMessage(null, msgSent, username, ChatMessageHue, MessageType.ChatSystem, 3, TextType.OBJECT, true)` (4226) → `EventSink.InvokeRawMessageReceived` (`MessageManager.cs:98`), `EventSink.InvokeMessageReceived` (`MessageManager.cs:303`).
- **Ignores / partial** — no `World.InGame`/Player guard, yet `ProfileManager.CurrentProfile.ChatMessageHue` is dereferenced at 4194, 4202, 4226, 4267. 0x03ED reads the accepted username, discards it, and unconditionally joins "General" instead of the named channel (4165-4167). 0x03EE, 0x03EF, 0x03F0 parse and apply nothing — no user list is kept. On 0x0025-0x0027 the first `{...}` run is stripped only when `}` follows an existing `{` (4216-4222). `MessageType.ChatSystem` falls through MessageManager's switch with no overhead text (`MessageManager.cs:119-120`). The default branch only runs for cmd 0x0001-0x0024 / 0x0028-0x002C (4232); all others fall out silently. The default branch returns early when `ChatManager.GetMessage(cmd-1)` is empty — true for any index >= 41 (`ChatManager.cs:91-94`) — so the trailing skip+text are never read (4239-4242). `%1` substituted only for non-empty text (4247); `%2` only for cmd-1 == 0x000A or 0x0017 (4256).

### 0xB8 CharacterProfile

- **Purpose** — A character's paperdoll profile text; the client opens the profile scroll.
- **Wire** — variable (`PacketsTable.cs` 0xB8 = -1), offset 3 (228). u32BE serial @3 (4283); ASCII null-terminated header (4284); UnicodeBE null-terminated footer (4285) — read BEFORE the body; UnicodeBE null-terminated body (4287).
- **Mutates** — UIManager gump list only: old ProfileGump for the serial removed (4289), new one added (4291).
- **Creates** — `ProfileGump(serial, header, footer, body, canEdit)` (4291); ctor builds GumpPic, ExpandableScroll, ScrollArea, Labels (`ProfileGump.cs:59-92`).
- **Destroys** — any existing ProfileGump under the same serial is disposed (4289).
- **Triggers** — no outgoing packets.
- **Ignores / partial** — returns if `!World.InGame` (4278) and the text is discarded, not cached. `canEdit` derives purely from `serial == World.Player.Serial` (4292); no server editability flag is read. Nothing is stored on the Entity — closing the gump loses the text. A truncated packet yields empty header/footer/body and still opens a gump, because `ReadString` returns `string.Empty` at/after end (`StackDataReader.cs:404-407`).

### 0xB9 EnableLockedFeatures

- **Purpose** — Declares which expansion/account features the client may use; client stores them and rebuilds the body-conversion animation table.
- **Wire** — length version-dependent: `PacketsTable.cs:370-377` gives 0x05 for `Client.Version >= CV_60142`, else 0x03; offset 1. off 1 u32BE → LockedFeatureFlags when >= CV_60142 (4300-4303); off 1 u16BE otherwise (4304-4307). Nothing else read.
- **Mutates** — `World.ClientLockedFeatures.Flags = flags` (4309 → `LockedFeatures.cs:84-87`; singleton at `World.cs:173`), read later by `GameActions.cs:1194`, `CharacterSelectionGump.cs:70/134/136`, `CreateCharAppearanceGump.cs:398`, `CreateCharTradeGump.cs:174`, `HouseCustomizationManager.cs:1996/2029`. `ChatManager.ChatIsEnabled` = Enabled or 0 (4311-4315; field `ChatManager.cs:41`), read by `GameActions.cs:466/480`, `SystemChatControl.cs:476`. `AnimationsLoader._bodyConvInfos` entries (4329 → `Animation.cs:323-325` → `AnimationsLoader.cs:532-636`), which re-reads Bodyconv.def and writes `_bodyConvInfos[index] = new BodyConvInfo{FileIndex, Graphic, AnimType, MountHeight}` (`AnimationsLoader.cs:626-632`; dictionary `:66`).
- **Creates** — BodyConvInfo entries (`AnimationsLoader.cs:626`); a DefReader over Bodyconv.def, opened and disposed (`AnimationsLoader.cs:544`).
- **Destroys** — nothing removed; ProcessBodyConvDef overwrites in place and never clears. The reload-from-scratch path is commented out (`Animation.cs:326-340`), so flags from a previous login are never undone, only overwritten where the def has a matching row.
- **Triggers** — synchronous disk I/O: Bodyconv.def re-parsed inside the handler (`AnimationsLoader.cs:539-544`). No outgoing packets, no gumps.
- **Ignores / partial** — read width chosen by LOCAL `Client.Version` (4300), not by the packet. Chat enabled solely on the T2A bit (4311-4313); every other combination assigns 0, so this packet can turn chat back off. BodyConvFlags mapping is not one-to-one (4317-4327): UOR → Anim1|Anim2, LBR → Anim1, AOS → Anim2, SE → Anim3, ML → Anim4, OR-accumulated. `ProcessBodyConvDef` returns immediately if `UOFileManager.Version < CV_300` (`AnimationsLoader.cs:534-537`) or the def file is missing (`:541-542`) — flags stored, table untouched. In the loop, column 1 rows are skipped without Anim1 and column 2 rows without Anim2 (`:559-572`); columns 3 and 4 are accepted regardless because those checks are commented out (`:576-590`). Rows with body < 0 skipped (`:553-556`); rows for an absent file index skipped (`:621-623`). Mount-height overrides are hard-coded per index rather than read from file (`:592-619`). This rewrites the shared body-conversion table that `ConvertBodyIfNeeded` (`Animation.cs:343+`) reads while mobiles are drawn.

### 0xBA DisplayQuestArrow

- **Purpose** — Show or hide the on-screen arrow pointing at a quest location.
- **Wire** — registered at 309; length 0x0A for CV_7090+ (`PacketsTable.cs:394`), else 0x06 (`:403`); offset 1. `[1]` bool display (4334); `[2..3]` u16BE mx (4335); `[4..5]` u16BE my (4336); `[6..9]` u32BE serial (4342), read only when `Client.Version >= CV_7090` (4340) — otherwise serial stays 0.
- **Mutates** — `QuestArrowGump._mx/_my` (`QuestArrowGump.cs:64-65`), via ctor (`:58`) or `SetRelativePosition` (4355); `UIManager.Gumps` (`UIManager.cs:485`). No World/Item/Mobile/Chunk state.
- **Creates** — `QuestArrowGump(serial, mx, my)` (4351); `LocalSerial = ServerSerial = serial` (`QuestArrowGump.cs:51`); its GumpPic child is created lazily on first Update (`:101`).
- **Destroys** — `arrow.Dispose()` when display is false and a matching gump exists (4362).
- **Triggers** — no outgoing packet; the gump re-derives direction and screen position every frame from `World.Player.X/Y/Z/Offset` (`QuestArrowGump.cs:84-121`).
- **Ignores / partial** — below CV_7090 the serial is never read and stays 0 (4340-4343), so every quest arrow shares LocalSerial 0 and a second arrow repositions the first instead of adding one. `display == true` with an existing gump only updates `_mx/_my` — no window reposition, no re-add (4353-4356). `display == false` with no matching gump does nothing (4360). No `World.InGame` guard in the handler; the gump self-disposes on its next Update if `!World.InGame` (`QuestArrowGump.cs:72-75`).

### 0xBC Season

- **Purpose** — Change the world season (and, in stock clients, season music — which this fork deliberately does not play).
- **Wire** — fixed 0x0003 (`PacketsTable.cs:229`), offset 1. `[1]` u8 season (4376); `[2]` u8 playSound — read as the season's play-sound boolean, not a music track index (4378-4382), and passed only to the diagnostics logger.
- **Mutates** — `World.OldSeason` (`World.cs:91`) at 4396; `World.OldMusicIndex = 42` (`World.cs:97`) at 4400; `World.Season` (`World.cs:90`, private setter) inside ChangeSeason at `World.cs:208`; every GameObject in every used chunk has its Graphic rewritten — `World.cs:210-222` walks `Map.GetUsedChunks()` and all 8x8 cells calling `UpdateGraphicBySeason()`, which for Multi rewrites Graphic and IsVegetation (`Multi.cs:106-107`).
- **Creates / Destroys** — nothing.
- **Triggers** — `MusicDiagnostics.SeasonPacket(season, playSound)` (4384 → `MusicDiagnostics.cs:120`); `World.ChangeSeason` (4404). No music: ChangeSeason's music parameter defaults to -1 and the `music < 0` guard returns before `Audio.PlayMusic` (`World.cs:224-233`).
- **Ignores / partial** — returns if `World.Player == null` (4371). `season > 4` is clamped to 0 rather than rejected (4386-4389). If the player is dead and the season is 4 (Desolation) the whole packet is dropped — OldSeason not written, ChangeSeason not called (4391-4394). The Desolation music-index write at 4400 tests `World.Season`, i.e. the season still in effect, not the incoming one. The second wire byte is never used as a track number in this fork, so stock's play-on-season-change is gone (comments 4378-4381, 4403).

### 0xBD ClientVersion

- **Purpose** — Server asks the client to state its version string.
- **Wire** — variable (`PacketsTable.cs:230` = -1), reader seeked to 3 (227-228, `:191`), but the handler never touches `p`; the server payload is discarded in full.
- **Mutates** — no world/client state. The reply string is only read: `Settings.GlobalSettings.ClientVersion` (4409).
- **Creates** — `Send_ClientVersion` allocates a StackDataWriter (64 bytes since `GetPacketLength(0xBD) < 0`), writes ID 0xBD, two zero bytes, `WriteASCII(version)`, back-patches the u16BE length at offset 1, sends and disposes (`OutgoingPackets.cs:915-935`).
- **Destroys** — nothing.
- **Triggers** — OUTGOING 0xBD via `NetClient.Socket.Send_ClientVersion` (4409).
- **Ignores / partial** — unconditional: no `World.InGame`/Player guard, so it answers even at the login scene. It sends whatever `Settings.GlobalSettings.ClientVersion` holds, never anything derived from the request. An identical call also exists at 1022 in a different handler, so the reply has two independent sources.

### 0xDD OpenCompressedGump

- **Destroys** — both rented arrays returned in finally blocks (5714, 5799); the StackDataReader is Release()d (5775). CreateGump disposes nothing; the reuse path Clear()s an existing gump's children (6954).
- **Triggers** — `ZLib.Decompress` twice (5706, 5744); CreateGump → `UIManager.Add`, `gump.Update`, `gump.SetInScreen` (7532-7536); `HtmlCrashLogGen.Generate` on any exception from the second half (5807).

Per line, fewer than 2 bytes remaining yields `string.Empty` (5769-5772) and a length of 0 also yields empty (5766) — the loop never aborts on truncation, it fills the rest with empties. Every failure from `p.Skip` through CreateGump is swallowed into `HtmlCrashLogGen.Generate` (5805-5808); because CreateGump is inside that try, a partly-constructed gump can already be in `UIManager.Gumps` (7532) before the exception is caught. There is no `World.Player` null guard here, unlike OpenGump at 4066 — but CreateGump null-checks World.Player before writing HasGump (7622). The layout is decoded as UTF8 over the full dlen (5708), including any trailing NUL padding.

### 0xF5 DisplayMap

- **Purpose** — Open a treasure-map / multimap window for an item, giving the world rectangle it covers.
- **Wire** — registered for 0x90 (287) and 0xF5 (344); lengths 0x13 and 0x15 (`PacketsTable.cs:185` and the 'f5' row); offset 1. `[1..4]` u32BE serial (3405); `[5..6]` u16BE gumpid (3406) — read and then never used; `[7..8]` u16BE startX (3407); `[9..10]` u16BE startY (3408); `[11..12]` u16BE endX (3409); `[13..14]` u16BE endY (3410); `[15..16]` u16BE width (3411); `[17..18]` u16BE height (3412); `[19..20]` u16BE facet, read only when `p[0] == 0xF5` (3423-3426).
- **Mutates** — `Item.Opened = true` for the serial (3454; field `Item.cs:249`) — the only world-object write, and what later makes `Item.Destroy` dispose this MapGump (`Item.cs:281`); MapGump mapX/mapY/mapEndX/mapEndY/mapFacet written by MapInfos (`MapGump.cs:186-190`) called at 3430 or 3436; `MapGump.Width`/`Height` overwritten from the created texture's dimensions and `_mapTexture` replaced (`MapGump.cs:172-178`) — the packet's width/height only reach the constructor (3414) and the ResizePic sizing (`MapGump.cs:71-72`); `UIManager.Gumps` prepend (3448 → `UIManager.cs:485`).
- **Creates** — `MapGump(serial, gumpid, width, height)` (3414) — `base(serial, 0)`, so LocalSerial = serial and ServerSerial = 0 (`MapGump.cs:57`); children ResizePic 0x1432, three Buttons, a HitBox, a GumpPic 0x0139D, a MenuButton with a four-entry ContextMenuControl (`MapGump.cs:67-164`); a Texture2D built from MultiMapLoader pixel data (`MultiMap.cs:29-35`); later, on user interaction, a WorldMapGump can be fetched and marked/pathfound to (`MapGump.cs:106-157`).
- **Destroys** — `MapGump.SetMapTexture` disposes the previously held texture (`MapGump.cs:172`). Nothing else — no existing MapGump for the same serial is disposed.
- **Triggers** — `MultiMapLoader.Instance.LoadFacet` or `LoadMap` via `Client.Game.MultiMaps.GetMap` (3428/3434 → `MultiMap.cs:22-24`); `UIManager.Add` (3448); deferred `Pathfinder.WalkTo`, `WorldMapGump.GoToMarker` and `AddUserMarker` from the context menu (`MapGump.cs:114, 117, 130, 133, 154, 157`).
- **Ignores / partial** — no `World.InGame`/Player guard at all. facet is only read from the wire for `p[0] == 0xF5` (3423); for 0x90 on a client >= CV_308Z the local stays 0 and is passed as facet 0 to GetMap and MapInfos (3428, 3430) — not as "no facet"; only 0x90 on a client < CV_308Z takes the null/-1 path (3434, 3436). `MultiMap.GetMap` falls back from LoadFacet to LoadMap when no such facet exists (`MultiMap.cs:22-24`), and returns default (Texture == null) when the pixel span is empty or Width/Height <= 0 or > 8192 (`:26-27`); SetMapTexture is then skipped by the null check at 3439 and the gump keeps its constructor-time size. Any exception during texture creation is caught, logged and swallowed (3442-3446); the gump is still added at 3448. `World.Items.Get(serial)` may be null (3452) — then `Opened` is never set, and nothing owns the gump to dispose it when the item goes away. Only `World.Items` is consulted, never World.Mobiles or World.Get. Every packet creates a brand-new MapGump; there is no lookup for an existing one, so repeated packets stack gumps for the same serial. gumpid is decoded and then unused.

### 0xF7 PacketList

- **Purpose** — A batched container carrying N sub-packets in one frame; in practice only 0xF3 world-object updates.
- **Wire** — variable (`PacketsTable.cs` 0xF7 row = -1), offset 3. `[3..4]` u16BE count (6295); per iteration u8 sub-packet id (6299); when id == 0xF3, `UpdateItemSA(ref p)` continues on the same reader (6303): Skip(2) (6083), u8 type (6084), u32BE serial (6085), u16BE graphic (6086), u8 graphicInc (6087), u16BE amount (6088), u16BE unk (6089), u16BE x (6090), u16BE y (6091), int8 z (6092), u8 Direction (6093), u16BE hue (6094), u8 Flags (6095), u16BE unk2 (6096) — 26 bytes per record including the id byte, matching the 0x1A standalone length of 0xF3. The loop has no `p.Position < p.Length` bound; it is driven solely by the count field.
- **Mutates** — everything UpdateGameObject writes, per sub-record (see 0xF3): item Graphic/X/Y/Z/LightID/Layer/Hue/Amount/Flags/Direction (6663-6692), multi flags and WantUpdateMulti when type == 2 (6656-6663), IsDamageable when type == 3 (6667), mobile Graphic/Hue/Flags/position/steps (6710-6731), chunk relink via SetInWorldTile (6770, 6800 → `GameObject.cs:267-271` → `Chunk.cs:178-180`); `World.Items[serial]` / `World.Mobiles[serial]` insertion (`World.cs:577` / `:601`). Player self-update path (reachable only from 0xF7, see below): `World.RangeSize.X/.Y` (6831-6832), Player.Graphic (6839), Direction (6840), Hue via FixHue (6841), Flags (6842), `Walker.WalkingFailed = false` (6838), `Walker.DenyWalk` (6843), `Walker.ResendPacketResync = false` (6874), Player X/Y/Z + chunk relink (6876), CloseBank (6837), CloseRangedGumps (6875), UpdateAbilities (6877), `GameScene.UpdateDrawPosition = true` and `Weather.Reset` (6849-6850). `World.Season` and every used chunk's objects when the player's dead state flips (`World.cs:208, 218` via 6866 or 6870). `ItemHold.UpdatedInWorld` / `Enabled` / `Dropped` (6585, 6794-6795).
- **Creates** — Item instances from `Item._pool` (`Item.cs:257` via `World.GetOrCreateItem`, `World.cs:576-577`); Mobile instances from the mobile pool (`World.cs:600-601` via GetOrCreateMobile). No gump is created directly; ContainerGump/GridContainer/etc. only get RequestUpdateContents.
- **Destroys** — destroyed entities still filed under a reused serial are removed and pooled (`World.cs:565/569` items, `:589/593` mobiles). UpdatePlayer's CloseRangedGumps (6875) and CloseBank (6837) dispose gumps. `World.ChangeSeason` on a death-state flip does not destroy, and InternalMapChangeClear is not reached from here.
- **Triggers** — `Log.Warn($"Unknown packet ID: [0x{id:X2}] in 0xF7")` (6307); `EventSink.InvokeOnItemCreated`/`InvokeOnItemUpdated` (6695, 6697); `EventSink.InvokeOnCorpseCreated` (6807); `GameActions.SingleClick` → Send_ClickRequest (6740, 6747); `GameActions.RequestMobileStatus` → status request (6777); `World.Player.TryOpenCorpses` → `GameActions.DoubleClickQueued` per nearby corpse (6118 and 6810, `PlayerMobile.cs:1454`); `HouseDiagnostics.LogRangeProbe` / `LogHouseItemArrived` (6758, 6802); `Audio.PlayMusic` on a death-state flip (`World.cs:232`).
- **Ignores / partial** — whole packet ignored when `World.Player == null` (6290-6293). Any sub-packet id other than 0xF3 aborts the loop with a warning and leaves the rest of the payload unparsed (6305-6310); the reader is not resynchronised. The loop trusts the count field alone; there is no check that the reader still has 25 bytes left before each UpdateItemSA call. Inside UpdateItemSA the player-self branch is gated on `p[0] == 0xF7` (6121) — the same code reached as a standalone 0xF3 silently drops any update addressed to the player, and when `serial == World.Player` and the outer packet is not 0xF7 neither UpdateGameObject nor UpdatePlayer runs (6098/6121), leaving the record entirely unapplied. UpdateItemSA re-checks `World.Player == null` (6078) even though PacketList already did. The extra TryOpenCorpses at 6116 only fires when graphic == 0x2006 and `AutoOpenCorpses`; TryOpenCorpses further bails on `TargetManager.IsTargeting` or IsHidden depending on CorpseOpenOptions (`PlayerMobile.cs:1439-1447`) and skips corpses beyond AutoOpenCorpseRange or already in AutoOpenedCorpses (`:1451`). In UpdateGameObject, mobiles are only created when `type != 3` (6594); a type == 3 mobile serial is created as an Item and marked IsDamageable (6667). type == 2 sets IsMulti and only raises WantUpdateMulti when the masked graphic, position or hue actually differ (6657-6662). amount of 0 is rewritten to 1 (6684-6687). Mobile graphic is masked with 0x3FFF (6729); item graphic is left unmasked except in the multi branch (6663). graphic_inc is not added when graphic == 0x2006 (6649-6652). UpdatePlayer discards the serverID argument entirely and masks the direction with `Direction.Mask` (6840).
