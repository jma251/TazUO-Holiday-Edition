# net-transport

Partition = `src/ClassicUO.Client/Network/*.cs` minus `PacketHandlers.cs`, `OutgoingPackets.cs`,
`PacketsTable.cs`, `Enhanced*.cs`. 12 files, 5436 lines, all read in full.

Scope: TCP socket ownership, the send/receive byte pipeline (encrypt → Huffman → queue),
the UO encryption stack (login XOR stream, Blowfish, Twofish+MD5), the packet hex logger,
network statistics/ping, and the native/managed plugin host (which lives in this folder
because plugins hook packet send/recv).

## Timing

- **Receive thread** (`AsyncSocketWrapper.ReceiveLoopAsync`, AsyncNetClient.cs:91): a `Task.Run` loop, `await Task.Delay(1)` per iteration (~1 ms poll, in practice the OS timer floor ~15 ms on Windows). Reads only `min(4096, Socket.Available)` bytes (:99), allocates an exact-size `byte[]` per read (:114), raises `OnDataReceived`.
- **`OnDataReceived`** (AsyncNetClient.cs:338) runs **on the receive thread**: decrypt in place → Huffman decompress into the shared `_uncompressedBuffer` → `ToArray()` → enqueue.
- **Network/send loop** (`NetworkLoopAsync`, AsyncNetClient.cs:307): separate `Task.Run`, per iteration calls `ProcessSendAsync` + `Statistics.Update()` then `await Task.Delay(1)`.
- **`NetStatistics.Update()`** (NetStatistics.cs:146) recomputes deltas at most every **500 ms** (`_statisticsTimer = Time.Ticks + 500`) — but it reads `Time.Ticks`, which is written on the frame thread (GameController.cs:470).
- **Frame thread packet drain**: `GameController.ProcessNetworkPackets()` (GameController.cs:138) runs once per `Update`, bounded by `MAX_PACKETS_PER_FRAME = 25` (GameController.cs:136). Each dequeued buffer goes to `PacketHandlers.Handler.ParsePackets(message)`.
- **`Plugin.Tick()`** — once per frame, GameController.cs:481, immediately after packet processing and before `Scene.Update()`.
- **Ping**: in-game every **1000 ms** (GameScene.cs:899-902); at character select/creation every **60000 ms** (LoginScene.cs:230-236). `SendPing` stamps `_startTickValue` before sending (NetStatistics.cs:131).
- **Resync-on-hang**: GameScene.cs:905 fires `Send_Resync()` when `Time.Ticks - Statistics.LastPingReceived > 5000` and ≥5000 ms since last resync.
- **On connect**: `AsyncNetClient.Connect` (:253) clears send stream, resets Huffman + statistics, then starts `NetworkLoopAsync`.
- **On login relay** (LoginScene.HandleRelayServerPacket, LoginScene.cs:731-751): `Disconnect().Wait()` → new `AsyncNetClient` → `PacketHandlers.Handler.Reset()` → `EncryptionHelper.Initialize(false, seed, …)` → `Connect(...).Wait()` → `EnableCompression()` → raw 4-byte seed (`ignorePlugin:true, skipEncryption:true`) → `Send_SecondLogin`. **Blocking `.Wait()` calls on the frame thread.**
- **Plugin load**: once, from `Client.Load` (Client.cs:80) via `Plugin.Create`.
- **`EncryptionHelper.CalculateEncryption`**: once at Client.cs:197 from the detected client version.
- **Blowfish table rotation**: every `CRYPT_GAME_TABLE_TRIGGER = 21036` bytes of ciphertext (BlowfishBehaviour.cs:137, :227).
- **Twofish cipher-table refresh**: every 256 outbound bytes (`_rect_pos >= 0x100`, TwofishBehaviour.cs:233).

## Hazards

- **AsyncNetClient.cs:186 / :350 / :453** — `_uncompressedBuffer` is a single shared 64 KB buffer written by `DecompressBuffer` on the receive thread; the result is copied by `ToArray()` at :350 before enqueue, so the copy is what protects it. Any future path that enqueues the span itself instead of the array would alias.
- **AsyncNetClient.cs:451** — `var size = 65536;` is passed as the capacity limit each call, but `_uncompressedBuffer` is `BUFF_SIZE = 0x10000` = 65536, so a single receive that decompresses to exactly the cap returns `false` from `Huffman.Decompress` (Huffman.cs:354) and forces a disconnect.
- **AsyncNetClient.cs:455-456** — `DecompressBuffer` failure calls `_ = Disconnect()` (fire-and-forget async) *and* raises `Disconnected` from the receive thread, while `Disconnect()` itself awaits `_networkTask`; the discarded Task is never observed.
- **AsyncNetClient.cs:270-276** — `_isDisconnecting` is latched and never reset. After one `Disconnect()`, the same `AsyncNetClient` instance can never disconnect again; reconnect works only because `LoginScene` replaces the whole singleton (LoginScene.cs:390, :737).
- **AsyncNetClient.cs:157-168** — same latch in `AsyncSocketWrapper.Disconnect()`; `_receiveTask?.Wait(5000)` blocks the caller, and when the caller *is* the receive loop (`Disconnect()` from inside the catch handlers at :124/:137/:142/:148) it waits on its own task.
- **AsyncNetClient.cs:99-102** — `ReceiveLoopAsync` only reads when `_socket.Client.Available > 0`; when it is 0, `bytesRead` stays `-1`, so the `bytesRead == 0` graceful-close branch at :104 is never taken for a peer FIN that arrives with no pending data. Close is then only detected via `IsConnected` or an exception.
- **AsyncNetClient.cs:114** — a fresh `byte[bytesRead]` is allocated for every socket read, on the receive thread, at up to ~1000 reads/sec.
- **AsyncNetClient.cs:426** — `ProcessSendAsync` allocates a new 4096-byte array on every loop iteration that has data, i.e. potentially every millisecond.
- **AsyncNetClient.cs:424-436** — only one 4096-byte chunk is dequeued per `NetworkLoopAsync` iteration; a burst larger than 4096 bytes drains at 4 KB per ~1 ms tick. (Legacy `NetClient.ProcessSend` at NetClient.cs:336 loops until empty.)
- **AsyncNetClient.cs:214** — `Socket` is a public settable static; `LoginScene.cs:390` and `:737` replace it. Any code holding the previous instance (event subscribers, in-flight `Send`) keeps talking to a dead client. `LoginScene.cs:179/387` unsubscribe `Connected` from whichever instance `NetClient.Socket` currently resolves to, which is not necessarily the one subscribed.
- **AsyncNetClient.cs:317** — `Statistics.Update()` is called from the network thread while `Statistics.TotalBytesReceived` is incremented from the receive thread (:342) and `TotalBytesSent`/`TotalPacketsSent` from the caller thread (:400-401); the `uint` fields are unsynchronised.
- **AsyncNetClient.cs:342 / GameController.cs:144** — `TotalBytesReceived` written on the receive thread, `TotalPacketsReceived` on the frame thread, both non-atomic `+=`.
- **NetStatistics.cs:148-150** — `Update()` compares against `Time.Ticks`, which is assigned on the frame thread (GameController.cs:470) and read here from the network thread.
- **NetStatistics.cs:106** — `PingReceived(idx)` indexes `_pings[idx % 5]` with a server-supplied index and computes `Time.Ticks - _startTickValue`; `_startTickValue` is overwritten by every `SendPing`, so with a 1 s send interval an out-of-order or delayed reply measures against the wrong send.
- **NetStatistics.cs:39-56** — two constructors, one storing `_socket` (NetClient) and one `_asocket`; `SendPing` (:110) branches on which is non-null. The `NetClient` branch's send is commented out (:120), so a `NetStatistics` built from a `NetClient` silently never pings.
- **NetStatistics.cs:77** — `LastPingReceived` is initialised to `Time.Ticks` at field-initialiser time (before the frame loop has set `Time.Ticks`, i.e. 0), which the resync-on-hang check at GameScene.cs:905 reads.
- **Encryption.cs:50-56** — the three cipher behaviours and `KEY_*`/`Type` are process-static. Cipher stream position (`Blowfish._stream_pos`, `Twofish._rect_pos`, `_send_pos`) is **not** reset by `AsyncNetClient.Connect`; only an explicit `EncryptionHelper.Initialize` resets it (LoginScene.cs:574, :739).
- **Encryption.cs:194-200** — `Decrypt` is a no-op for every type except `TWOFISH_MD5`, while `AsyncNetClient.ProcessEncryption` (:404) calls it unconditionally once compression is on.
- **TwofishBehaviour.cs:247** — `Decrypt` dereferences `_xor_data`, which is only allocated when `Initialize(seed, use_md5: true)` ran (:215). `Initialize(seed, false)` (the `BLOWFISH__2_0_3` path, Encryption.cs:132) leaves `_xor_data` null.
- **TwofishBehaviour.cs:233-239** — `_rect_pos` is `ushort` and the guard `if (_rect_pos >= 0x100) refreshCipherTable()` runs *before* the increment, so the table is refreshed exactly at 256-byte boundaries; `Encrypt` mutates shared static-singleton state from whichever thread calls `AsyncNetClient.Send`.
- **AsyncNetClient.cs:372-402** — `Send` is called from the frame thread, from `LegionScripting`, and from plugin callbacks (`Plugin.cs:767`, `:790`). `EncryptionHelper.Encrypt` at :392 mutates the shared cipher stream with no lock; only the `CircularBuffer` enqueue is locked (:395).
- **AsyncNetClient.cs:392** — encryption is done **in place** over the caller's span (`src == dst == message`); the caller's buffer is destroyed. Many `OutgoingPackets` senders use `stackalloc`, so this is intentional but means a span can never be re-sent.
- **Plugin.cs:583-584 / 596-597** — `ProcessSendPacket` re-slices the caller's span to the plugin-reported `length` and copies back. If a plugin *grows* `length`, `message.Slice(0, length)` throws or aliases past the original packet; there is no bound check against the original length.
- **Plugin.cs:540-548** — `ProcessRecvPacket` copies `data` into `tmp` sized by the **incoming** `length`, then after the plugin possibly changes `length` copies `tmp`→`data` using the **new** `length`; a grown length reads past `tmp` / writes past `data`.
- **Plugin.cs:523-536, 571, 619-696, 702, 721, 734** — every dispatch is a `foreach` over the static `Plugins` list while calling into plugin code that can call back into the client; `OnClosing` (:614) clears the list.
- **Plugin.cs:213-266** — `PluginHeader header` is a local struct; `void* func = &header` (:234) is handed to native `Install`. The pointer is stack-scoped, and the header's callback fields are read back after the call (:312-413). A plugin that retains the pointer holds a dangling stack address.
- **Plugin.cs:1305-1307** — `resources[destroyResourceCommand.id]?.Dispose()` indexes before checking presence; a destroy for an unknown ID throws `KeyNotFoundException` inside the render path. Same pattern at :1034, :1041, :1048, :1055, :1065, :1081, :1154, :1165, :1201, :1247 — all direct indexer reads on plugin-supplied IDs.
- **Plugin.cs:1183-1205** — `CMD_CREATE_BASIC_EFFECT` sets `current_effect` only in the *else* (already-exists) branch; the first creation leaves `current_effect` null for the following draw.
- **Plugin.cs:130** — `_resources` keys are `IntPtr` IDs chosen by the plugin; `CMD_DESTROY_RESOURCE` removes the entry, and a later create can reuse the same ID for a different resource type while a `as VertexBuffer`/`as Texture2D` cast elsewhere silently yields null.
- **Plugin.cs:755-758 / 777-780** — plugin recv callbacks `Append` to `PacketHandlers.Handler` under a lock, from whatever thread the plugin uses; the frame thread drains via `ParsePackets` (GameController.cs:142) with no such lock visible at the drain site.
- **Plugin.cs:664-671** — `ProcessHotkeys` dereferences `UIManager.SystemChat.TextBoxControl` in the same expression that guards `UIManager.SystemChat != null`, but the `||` arm at :670 is reached when the left arm is false — including when `ProfileManager.CurrentProfile` is null.
- **CircularBuffer.cs:104-106** — growth condition is `Length + size >= _buffer.Length`; after `SetCapacity`, `_head=0`, `_tail=Length`, so the `_head < _tail` branch at :109 is taken and the wrap-copy at :119-120 relies on capacity being strictly greater than `Length+size`.
- **CircularBuffer.cs:109-126** — when `_head == _tail` and `Length > 0` (a full buffer), the `else` branch at :123 copies without wrapping; the growth check above is what prevents reaching that state.
- **CircularBuffer.cs:202** — `DequeSegment` hands out an `ArraySegment` over the live `_buffer`, which a later `Enqueue`/`SetCapacity` can overwrite or replace. Not called anywhere in this partition.
- **CircularBuffer.cs:38** — no internal locking; correctness depends on every caller holding `lock (_sendStream)`.
- **Huffman.cs:299-360** — decoder state persists across calls; a mid-symbol packet boundary is handled, but `Reset()` is only called on connect/`EnableCompression`/disconnect. If a decompress fails and the connection is not actually torn down, the tree position stays corrupt.
- **Huffman.cs:313** — `dest.Clear()` zeroes the entire 64 KB `_uncompressedBuffer` on every received segment.
- **PacketLogger.cs:41** — the credential-masking condition is `(!contains(0x80) || !contains(0x91))`; with `LogPacketID` empty both are false→true, so masking applies, but adding only 0x80 to the filter still leaves the condition true and masks it.
- **PacketLogger.cs:30** — `message[0]` is read before any length check.
- **PacketLogger.cs:33-34** — a 256-char stack buffer seeds a `ValueStringBuilder` that then grows on the heap for any packet over ~4 lines of hex.
- **NetClient.cs:105** — legacy `SocketWrapper.Read` computes `toRead = Math.Min(buffer.Length, available - done)` and reads into `buffer[done]`, which can overrun when `done > 0` and `available - done > buffer.Length - done`. Dead path (see Files table) but the code is present.
- **NetClient.cs:122-126** — `Disconnect()` calls `Dispose()` on the socket, then the class is reused for a later `Connect` which allocates a fresh `TcpClient`.
- **BlowfishBehaviour.cs:137-160** — `Encrypt` recurses into itself for the pre-rotation remainder; `index_in`/`index_out` are advanced but the recursive call passes the *unsliced* `src`/`dst` spans, so the post-trigger bytes are encrypted from offset 0 of the span rather than from `index_in`.
- **BlowfishBehaviour.cs:56** — `InitTables` loops `key_index < CRYPT_GAME_KEY_COUNT - 1` (24 of 25), so `p_table[24]`/`s_table[24]` are allocated at :48/:53 but left zero-filled; `_table_index` cycles mod 11 so index 24 is unreachable in practice.
- **BlowfishBehaviour.cs:129 vs :152** — `Initialize` seeds from `g_seed_table[0][...]`, rotation seeds from `g_seed_table[1][...]`.
- **MD5Behaviour.cs:50-73** — `Buffer/Input/Digest` return `ref` into a `fixed` block that has already exited; the refs escape the pin.
- **MD5Behaviour.cs:184-185** — `Finalize` calls `Update` with the padding and then subtracts `paddingLength` from `ctx.Size`, mutating the length counter after hashing.
- **AsyncNetClient.cs:374** — `if (!IsConnected || message == null || ...)`: `message` is a `Span<byte>`, so `message == null` is the empty-span comparison, not a null check.
- **LoginScene.cs:733, :741** — `Disconnect().Wait()` and `Connect(...).Wait()` block the frame thread on tasks whose continuations may need it.

## Fork deltas

Looks like TazUO / Holiday additions rather than stock ClassicUO:

- **`AsyncNetClient.cs` in its entirety** — stock ClassicUO ships only the synchronous `NetClient`/`SocketWrapper`. The async client, its background receive task, the `ConcurrentQueue<byte[]>` inbox and `TryDequeuePacket` are a rewrite. `NetClient.Socket => AsyncNetClient.Socket` (NetClient.cs:164) is the shim that keeps every stock call site compiling.
- **`NetClient.cs` reduced to a shim** — the instance transport is kept but orphaned; `NetStatistics` still carries a dual constructor (NetStatistics.cs:48/53) and a commented-out `_socket.Send_Ping` (:120) from that transition.
- **`Game.Managers.HouseDiagnostics.LogPacket(message, true)`** at AsyncNetClient.cs:388 and NetClient.cs:304 — Holiday-Edition diagnostics, added in commit `3c17e9667` "Log every packet, compactly, so an empty house can be seen on the wire".
- **`PacketLogger.LogPacketID` filter list** (PacketLogger.cs:11, :30, :41) and the 0x80/0x91 credential masking — TazUO addition over stock's unconditional dump; wired to a `Main.cs:528-542` command-line switch.
